# one-brackets-cli

[English](README.md) | **Русский**

Утилита командной строки для скобочных файлов 1С:Предприятия (`{1,"text",{nested,list}}`) на основе
библиотеки [`one-brackets`](https://crates.io/crates/one-brackets). Переводит их в JSON, YAML и XML и
обратно без потерь: экспорт и последующий импорт дают исходный файл байт в байт.

```sh
cargo install one-brackets-cli
```

## Команды

```sh
one-brackets export Form.txt -o Form.yaml        # формат по расширению
one-brackets export Form.txt --to json --compact # в стандартный вывод, одной строкой
one-brackets import Form.yaml -o Form.txt        # пишет BOM, как платформа; --no-bom без него
one-brackets check *.txt                         # код возврата 1, если какой-то файл повреждён
one-brackets fmt Form.txt -o Form.txt            # переписать в раскладке платформы
one-brackets get Form.txt 1.0.2                  # узел по индексам элементов; --raw, --to json
```

`-` означает стандартный ввод или вывод. В ошибках указаны строка и столбец:

```text
error: failed to read `Form.json`: atom "a b" at line 12, column 7 contains whitespace: use a quoted string instead
```

Журнал регистрации (`*.lgp`) читается по одной записи и выводится как JSON Lines, документы YAML
или XML `<values>`:

```sh
one-brackets export 20260908000000.lgp --lines --skip-lines 3 > records.jsonl
```

## Отображение

В скобочном формате три вида значений: списки, строки в кавычках и атомы без кавычек (числа,
GUID, литералы). Каждый формат их различает.

| Скобки | JSON | YAML | XML |
|---|---|---|---|
| `{1,2}` | `[1, 2]` | последовательность | `<list>…</list>` |
| `"текст"` | `"текст"` | `"текст"` (всегда в кавычках) | `<str>текст</str>` |
| `42`, `-0.5` | `42`, `-0.5` (текст сохраняется) | `42` | `<atom>42</atom>` |
| `N`, GUID | `{"atom": "N"}` | `N` (без кавычек) | `<atom>N</atom>` |
| пустой атом | `null` | `~` | `<atom/>` |

- **JSON.** Атом пишется числом, только если он является числом JSON; `007` и `1.` пишутся как
  `{"atom": …}`. `{"str": …}` читается как строка. `--plain` пишет остальные атомы строками:
  так читать проще, но импортировать результат обратно нельзя.
- **YAML.** Значения без кавычек — атомы, в кавычках и блочные — строки, как бы они ни выглядели.
  Атомы, которые нельзя записать без кавычек (base64 с переводами строк, `-`, `a:`, `[x]` и т. п.),
  помечаются тегом: `!atom "…"`. `!str` и `!!str` обозначают строки. Словари, ссылки (alias)
  и другие теги — ошибка.
- **XML.** `\r` и управляющие символы пишутся ссылками на символы; пробелы между элементами
  не учитываются, текст внутри `<str>` и `<atom>` сохраняется как есть.

Списки из одних значений пишутся в одну строку, остальные — по элементу на строку;
`--compact` пишет всё в одну строку.

При импорте ошибкой считается атом, который скобочный парсер прочитал бы иначе (с `,`, `{`, `}`,
пробелами или кавычкой в начале).

## Глубина

Преобразования не рекурсивны, поэтому глубоко вложенные файлы не переполняют стек. Исключение:
парсер YAML читает не больше 255 уровней в flow-стиле (`[[…]]`). У блочного стиля, который
`export` пишет по умолчанию, такого ограничения нет; YAML с `--compact` глубже этого импортировать
обратно нельзя.
